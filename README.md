# Excel 数据清洗助手

一个基于 Python、PySide6、pandas 和 openpyxl 的 Windows 桌面工具。当前版本为 **V0.9**，新增多列批量清洗工作台：各列独立配置、统一只读预览、确认后整批应用与一次撤销。所有转换均先预览再确认，支持撤销、恢复及安全导出。现有整表扫描、单列诊断、直接清洗及两种安全导出模式继续可用，源 Excel 不覆盖。

## 当前功能

- 中文主窗口，初始尺寸 1200 × 750。
- 统一的浅色现代界面：绿色主操作、卡片分区、问题统计徽标和文件打开引导；右侧规则区支持滚动。
- “工作数据 / 数据质量总览 / 数据诊断 / 清洗预览 / 辅助列预览 / 批量清洗”六个页签共用完整工作区；切换页面保留选列、检测结果、规则及预览。工作数据页展示 `working_df`，表格仍不允许直接编辑。
- 紧凑标题栏和通用工具栏；所有页面都可以发起“开始检测”，“适应列宽”调整当前页的表格。
- “展开清洗设置 / 收起清洗设置”控制右侧面板，记住各页面的展开状态和侧栏宽度。工作数据和诊断默认收起，清洗预览默认展开。
- 通过“打开 Excel”选择 `.xlsx` 文件，默认预览第一个工作表。
- 自动列出全部工作表，切换下拉框后刷新数据。
- 第一行作为字段名，显示数据行号，可横向和纵向滚动；表格只读。
- 拖动表头分隔线调整列宽；双击表头调整单列，点击“适应列宽”调整当前表格的所有列。调整后仍可手动拖动，宽列支持按像素横向滚动。
- 悬停单元格查看完整内容；双击单元格打开只读文本窗口，支持自动换行、滚动、选择及复制长文本。
- 点击表头选择并高亮整列，显示“当前选择列”；切换工作表或文件后清空选择。
- 底部显示当前文件名、工作表、总行数、总列数及当前 Sheet 的修改状态；标题 `*` 表示工作簿中至少一个 Sheet 有修改。
- 操作完成提示临时显示在状态栏左侧，结束后恢复文件和 Sheet 信息；右侧计数和修改状态始终可见。
- 后台读取文件；读取失败时显示中文提示并保留已有预览。
- 点击顶部“扫描当前工作表”，后台只读扫描全部字段，支持进度和取消，不要求先选列。
- 总览显示九类统计、受影响唯一行数、质量分、等级和摘要，默认问题优先，支持表头排序及点击字段进入已有单列流程。
- 各 Sheet 保存最近一次完整统计；应用、撤销和恢复后提示重新扫描，未修改时切换直接复用。总览不会自动清洗。
- 选择列后点击“开始检测”，检测前后普通空格、CHAR(160)、Tab / 换行、空值、重复值、文本数字混合、前导0风险、日期异常及全角字符。
- 数据诊断区域显示当前列、数据行数、九类统计及只读问题明细；同一单元格的多类问题分别列出。
- 检测在后台线程运行，切换列、Sheet 或文件后清除旧结果；成功导入文件或切换 Sheet 后回到工作数据页。
- 检测完成后，在右侧“推荐清洗”中勾选或取消规则，生成当前列的临时清洗预览。
- 清洗预览展示 Excel 行号、原始值、清洗后值、发生的操作及是否变化，默认显示变化行及被安全保护的行，可勾选“显示未变化数据”。
- 显示总数据、发生变化、未变化及各类实际处理的单元格数；公式参考随规则和当前列更新。
- 生成有变化且有效的预览后启用“应用清洗”，确认范围与规则后只修改当前选择列的工作副本。
- 应用、撤销和恢复后立即清除旧结果，刷新工作数据并重新检测当前列；重新检测失败时保留修改和撤销能力，提示手动重试。
- 支持按工作簿操作顺序多步撤销，跨 Sheet 撤销时自动切换到相应工作表；空历史禁用撤销按钮。
- “恢复原始”经确认后恢复当前 Sheet 的所有列，恢复操作本身也可撤销。
- 已载入的 Sheet 分别缓存原始快照和工作副本，切换回来保留修改。打开新文件或显式重开同一文件后开始新的工作会话。
- 重复值可在“异常标注 / 辅助列”中生成检查列预览，确认后追加到工作副本最右侧；不删除、合并或修改原记录。
- 辅助列支持唯一命名、撤销、恢复、源字段修改后刷新及两种导出模式的公式输出；单独添加辅助列也可导出。
- 不修改或保存原始文件。
- “导出清洗结果”汇总所有已修改 Sheet，在确认窗口选择“原列更新”或默认的“新增对照列（公式）”，确认源文件、目标位置及变化数量后后台导出。
- 新增对照列模式为每个有当前修改的列生成一列“字段名_清洗后”，对全部数据行写入公式或高级处理的确认值，原始脏数据保留，重名字段自动加序号。
- 默认建议 `原名_已清洗.xlsx`，重名自动建议 `_1`、`_2` 等；不允许覆盖源文件或其他已有文件。
- 源文件只读，先复制到保存目录的随机临时文件，保存完成后发布为目标文件；失败时删除临时文件。
- 校验源文件 SHA-256、表头、行列结构和数据快照；公式目标拒绝修改，普通文本清洗后以 `=` 开头时仍保存为文本。

**应用清洗和辅助列只修改内存工作副本，导出只生成新文件。** 不覆盖源文件、不自动保存，不删除重复记录、填充空值、删除前导0、猜测修复无效日期或批量处理文件。不继续实现下一版本功能。关闭软件或成功重新打开文件后，上一会话的工作副本和历史会清空，需提前导出要保留的清洗结果。

## V0.9 多列批量清洗工作台

保留单列检测、预览与应用，新增“批量清洗”页签。只处理当前工作表，不跨 Sheet 一键清洗，不批处理多个文件，也不自动删除、合并重复或填充空值。

### 操作方法

1. 打开文件，进入“批量清洗”，点击“扫描并生成建议”。如果当前 Sheet 已有有效整表扫描结果，直接复用；也可从质量总览点击“打开批量清洗工作台”进入。
2. 在字段配置表勾选“是否处理”，点击字段，在右侧独立修改该列规则。每列配置互不影响，取消规则或关闭某列会清除旧批量预览。
3. 日期标准化须为该列勾选“我确认此字段是日期列”。存在原始前导0，或去空格/全角转换后出现前导0的列，整列禁止文本数字转换。文本数字与日期转换也不能同时开启。
4. 点击“生成批量预览”。预览不修改 working_df，不增加历史；后台显示逐字段进度并支持取消。默认仅显示变化，最多1000项；勾选“显示未变化数据”也只展示前1000项，保留完整实际统计。
5. 核对工作表、字段、Excel行号、原值、清洗后值、执行规则、是否变化及保留说明。修改行数按 Excel 行唯一统计，修改单元格按实际单元格统计，各字段分别统计。
6. 点击“应用全部清洗”，在确认窗口核对全部字段与规则、修改行和单元格数。取消保持原状态；确认后所有列一起提交到内存工作副本。一次“撤销”恢复整批，恢复原始和两种导出模式继续使用。
7. 应用、撤销、恢复或切换工作表后，旧批量预览清空；数据修改使整表缓存过期，需要重新扫描生成建议。重复值可从当前字段的“生成重复检查列”跳转到已有辅助列预览；空值、重复、无效日期和前导0等提示仍保留供人工判断。

### 规则、预览与历史

- 配置使用不可变的 `ColumnCleaningConfig`，包含字段物理位置、名称、启用状态、规则、提示及日期确认。字段以位置区分，重名表头不会共用配置。
- `batch_cleaner.recommend_batch_configs()` 复用整表统计，分别推荐首尾空格、NBSP、隐藏字符、全角、无前导0风险的混合文本数字和日期规则；重复值与空值只提示。全部纯文本数字不等于混合类型，可以明确手动选择数字转换。
- `generate_batch_preview()` 调用现有 `generate_cleaning_preview()` 和安全类型处理，仅复制目标 Series，不按规则复制整表。固定顺序共用 `cleaner.ALL_RULE_ORDER`：NBSP → Tab → 换行 → 回车 → 全角 → 首尾空格 → 文本数字 → 日期。批量隐藏字符策略为替换普通空格。
- 界面只保留变化样本和全部数据样本各至多1000条；完整目标列及真实变化位置独立保存。当前字段的原有逐行预览会短暂在后台生成，不累计所有字段的完整明细，因此应用不受样本限制。
- `WorkbookDataManager.apply_batch_preview()` 检查会话、Sheet、revision、源值、配置与统计；所有列写入一次候选 DataFrame，再刷新辅助标签，全部成功后才整体提交。中途失败不会留下部分列修改。
- `BatchCleaningAction` 在原有 undo_stack 只增加一个条目，包含全部变化列的前后 Series、原操作次数、修改列和导出规则快照。一次撤销逐列恢复整个操作及辅助标签，保留此前的单列/辅助列历史。
- 导出仍比较 original_df 和 working_df 的最终差异。批量规则进入各列既有的 column_rules；普通空白对照列生成公式，含高级类型转换的对照列保存确认值，重复辅助列继续生成正确引用的公式。
- 界面样本限量不代表分页读取文件；原始数据、工作副本和实际变化列仍驻留内存。批量取消在当前字段完成后生效，不发布部分预览。

## V0.8 高级数据类型检测与安全处理

本版仅新增文本数字混合、前导0风险、日期异常及全角字符，接入原有 `detector.analyze_column()` 与整表扫描。没有建立另一套检测系统，没有增加依赖。

### 检测与安全边界

| 类型 | 判定方式 | 安全处理 |
| --- | --- | --- |
| 文本数字混合 | 同列既有数值类型，又有纯数字字符串；统计其中的文本数字单元格 | 可生成“字段_类型检查”，或勾选“文本数字转数字” |
| 前导0风险 | 纯数字字符串的整数部分多于一位且以0开头，如 `00123`、`0008`；`0` 和 `0.5` 不属于风险 | 只标注，禁止自动删除前导0或转成数字 |
| 日期异常 | 非空值中至少60%可按明确格式解析，才自动启用日期异常检测 | 可生成日期检查列；转换必须勾选“我确认当前列是日期字段” |
| 全角字符 | U+FF01～U+FF5E 和全角空格 U+3000 | 可勾选“全角转半角”，预览确认后应用 |

纯数字文本支持 `100`、`12.5`、`-5` 等 ASCII 数字形式；普通文本 ABC、千分位、金额、百分比、科学计数法及含空白的字符串不直接转换。若先明确勾选去首尾空格或全角转半角，则后续规则基于该步骤结果判断。带前导0以及超过15位有效数字或无法可靠往返的文本保留原样，预览显示原因；数值类型、布尔值和缺失值不参与文本数字转换。单个文本数字或全列文本数字并不等于“混合”，不会仅因可转为数字就扣分。

日期按真实日历验证，支持原生 date/datetime、读取后为 datetime 的 Excel 日期，以及 `2026-10-10`、`2026/10/10`、`2026年10月10日` 等明确格式。日/月/年或月/日/年只有在顺序可确定时解析；`10/10/2026` 不存在月日交换歧义，而 `01/02/2026` 和 `01/02/03` 保留并标注歧义。无效日期 `2026-02-30`、普通文本 abc、不带日期格式的裸 Excel 序号和8位数字编码均不猜测为日期。

日期列名含“日期/时间/date/time”仅作为信息提示，不能绕过60%门槛。比例分母排除空值；用户可明确确认低比例列为日期字段，再生成检查列或转换预览。默认目标为 YYYY-MM-DD 字符串；不识别或含时分秒/时区的值保留，避免丢失信息。原生午夜日期视为正常，其他可解析格式标为“格式不统一”。统一格式不代表自动修复无效日期。

全角转换使用固定 Unicode offset，仅转换全角 ASCII 和全角空格，不对中文、圈号数字、连字及其他 Unicode 字符做 NFKC 归一化。

### 操作方法

1. 打开文件、选择原字段，点击“开始检测”，或先整表扫描再点击字段。诊断显示九类统计；总览右侧新增文本数字混合、前导0风险、日期异常、全角字符四列，可横向滚动。
2. 点击“展开清洗设置”，在“高级类型处理”勾选需要的转换。文本数字转换和日期标准化默认不勾选；日期标准化必须先明确确认字段含义。
3. 点击“生成清洗预览”，核对原值、清洗后值、操作和保留原因。默认同时展示变化行及被安全保护的行；其余未变化行可手动展开。
4. 点击“应用清洗”并确认，仅修改 working_df。每次实际转换都进入原有 undo_stack，撤销恢复转换前的值与类型；“恢复原始”同时清除所有新增辅助列。
5. 需要标注时，分别点击“生成类型检查列 / 生成前导0风险列 / 生成日期检查列”，查看预览后点击“应用辅助列”。按“原字段_检查类型”命名，同名从 _2 递增，追加在最右侧；源列修改或撤销时检查结果同步刷新。
6. 导出到新文件。原列更新仅写真实变化；新增对照列模式保留原值，高级类型处理列写入预览确认的值，普通空白清洗列仍使用公式。新三类辅助列保存 Python 分析标签，重复检查列保留既有精确公式；确认框会说明差别。源文件不覆盖。

问题记录允许重叠，但质量分继续按受影响的唯一行数计算。整表扫描一次收集字符及类型特征，再根据列上下文汇总混合类型与日期问题，不为每种新问题反复扫描整列或保存全表明细。新规则不自动推荐删除重复、填充空值或改写未知业务数据。

模块职责：`type_utils.py` 共用类型与日期解析；`type_cleaner.py` 返回安全转换结果及保留原因；`detector.py` 返回问题记录；`annotation_builder.py` 生成辅助标签与预览；`type_rules_panel.py` 管理规则与确认入口。所有转换沿用原预览、工作副本、撤销及 exporter，不把业务规则写进主窗口。

本版没有金额、百分比、电话、邮箱、身份证、地址、自定义正则、多列联合重复、AI、自然语言或多文件批处理功能。

## V0.7 重复检查辅助列

本版增加“异常标注 / 辅助列”，与修改原值的普通空格、NBSP、Tab、换行、回车清洗分开。重复数据可能有业务意义，因此只做“检测 → 标注 → 人工判断”，不删除、保留首条/末条、合并或自动修复记录。V0.7 提供重复检查列，V0.8 在下述流程基础上增加类型、前导0及日期检查；未实现独立空值检查、多条件或多字段联合判断。

操作步骤：

1. 打开 Excel，选择工作表和原始字段，点击“开始检测”；也可扫描整表后点击该字段。
2. 检测到重复值后，点击“展开清洗设置”，在“异常标注 / 辅助列”中点击“生成重复检查列”。无重复值时按钮禁用。
3. 自动进入“辅助列预览”，查看 Excel 行号、原值、辅助列结果和公式。重复组的每条记录均标为“重复”，其他非空值为“正常”，None / NaN / NA / 真空单元格 / 纯空字符串标为“空值”。此时工作副本、历史和源文件均不改变。
4. 点击“应用辅助列”，核对字段、名称、位置和统计后确认。辅助列追加到当前 Sheet 的最右侧；工作数据页显示并选中新增列。原始字段和记录数不变，取消确认保留预览。
5. 默认名称为“字段名_重复检查”；已有同名列时从“_2”开始递增，不覆盖原有字段。可再次对原字段生成另一列。
6. “撤销”删除最近添加的辅助列；“恢复原始”删除当前 Sheet 后来添加的全部辅助列并恢复清洗修改，恢复操作本身也可撤销。成功重新打开文件后开始新会话。
7. 点击“导出清洗结果”，选择新文件及两种模式之一。即使只应用了辅助列、没有清洗原值，也可以导出。两种模式均在最右侧写入辅助列表头和 Excel 公式，源文件和已有文件不覆盖。

实现与公式：

- `annotation_builder.py` 提供命名、重复标签、兼容公式和预览生成。标签复用 detector 的 `detect_duplicates()` 和 `is_empty_value()`，保留原始值比较，不去空格或转换类型。`P001 / P002 / P001` 对应“重复 / 正常 / 重复”；数字 0 与文本 `"0"` 分开，文本区分大小写，`* / ? / ~` 作为普通文字。
- 按本次确认的精确口径，使用旧版 Excel 的 `IF / IFERROR / SUMPRODUCT / EXACT / ISTEXT / ISNUMBER / ISLOGICAL` 等函数，不使用 COUNTIF 的大小写忽略或数字文本合并行为，也不使用 XLOOKUP、LET、动态数组或 CSE 数组公式。`.xlsx` 需要 Excel 2007 或更新版本；本机已用真实 Excel 核验公式。
- 公式已合并数值与布尔值判断、统一外层错误处理，缩短表达式，同时保持精确检测口径。
- 公式将源 Excel 错误值（例如 `#N/A`）与读取后的缺失值一致标为空值，并隔离错误，避免影响其他行的重复判断。
- `get_column_letter()` 按实际源字段位置生成列字母，数据位置 0 对应 Excel 第 2 行。例：源字段在 D 列且有四条数据，首条公式引用 `D2`，比较范围为 `$D$2:$D$5`，最后一条引用 `D5`。采用有限数据范围，避免将表头当重复值或对整列运行精确数组比较。
- 预览的公式由模型按可见行生成，避免为大表一次建立全部公式字符串。应用后 `working_df` 保存“重复 / 正常 / 空值”标签，`SheetData.annotations` 单独保存来源列位置和辅助列名，`original_df` 不添加列。
- `AnnotationAction` 加入现有 `undo_stack`。撤销时校验末尾列位置及名称，再删除该列和元数据。恢复原始时清空辅助列元数据，`RestoreAction` 保存恢复前的数据及元数据，因此撤销恢复可以完整还原。
- 后续清洗或撤销源字段时，会同步重新计算依赖该字段的辅助列标签，避免工作数据显示旧结果。新增、撤销或恢复辅助列会增加 revision，使质量总览缓存过期。软件生成的辅助列不可直接清洗或继续生成辅助列，需选择原始字段。
- exporter 只比较原有字段的值变化，另外核对已注册辅助列的结构和标签。原列更新模式引用已更新的原列；新增对照列模式若保留原始脏列，会将辅助公式引用调整到代表当前工作副本的“清洗后”列。辅助列始终位于所有原字段及清洗对照列的右侧，不在字段中间插入。
- 追加位置按实际数据宽度计算，保留右侧仅有格式的空列；不会覆盖已有数据或合并区域。原有 Excel 表格、筛选范围不自动扩大到辅助列。辅助列头按文本保存，即使字段名以 `=` 开头也不会变成公式。

导出公式需要在 Excel 中重新计算；软件设置打开后自动重算，未由 Excel 计算并保存前，其他程序用 `data_only=True` 读取可能得到空缓存。公式范围固定为导出时的数据行，新添加 Excel 行后需自行调整范围。精确公式在大表中的重算比 COUNTIF 更耗时。日期与数值在 Excel 中可能具有相同存储值；实际出现这类无法区分的混合字段时，会拒绝生成并提示人工核对，避免与现有检测口径不一致。

## 整表扫描与直接清洗操作

1. 启动软件，打开 `.xlsx` 文件，在下拉框选择工作表。无需先选择列。
2. 点击顶部“扫描当前工作表”，自动进入“数据质量总览”。扫描基于当前 `working_df`，显示进度、已完成字段和总字段数；需要中止时点击“取消扫描”。
3. 完成后查看字段数、总数据行、存在问题字段及正常字段。总览默认按质量分从低到高排序，也可点击其他表头排序；悬停查看完整摘要，横向滚动或拖动表头调整列宽。
4. 点击总览中的字段行，软件自动选择并高亮工作数据表中的对应列，后台加载同一套规则的完整单列明细，完成后进入“数据诊断”。也可继续沿用原流程：在工作数据页点击表头，再点击“开始检测”。
5. 点击“展开清洗设置”查看推荐规则，或切换到“清洗预览”页。可调整 CHAR(160)、Tab、换行、回车和首尾普通空格规则。隐藏字符默认替换为空格，也可直接删除；空值仅提示，重复值可单独生成检查辅助列；均不自动删除或填充。
6. 点击“生成清洗预览”，核对 Excel 行号、操作前后值、变化数。默认只显示变化行，可勾选“显示未变化数据”；双击值查看全文，收起侧栏增加表格宽度。
7. 有变化时点击“应用清洗”，确认工作表、字段、影响行数和规则后应用。只修改内存中的当前列，自动重新检测该列；取消确认保留预览和工作数据。
8. 已扫描的总览此时标记“待更新”，显示“当前数据已发生修改，请重新扫描工作表以更新质量总览。”再次点击“扫描当前工作表”，即可看到清洗后的统计，不会自动扫描大表。
9. “撤销”恢复最近一次操作；“恢复原始”经确认恢复当前 Sheet，恢复操作本身也可撤销。这些操作同样使该 Sheet 的总览缓存过期，需重新扫描。
10. 切换其他 Sheet 后可继续扫描、查看字段、预览和应用。各 Sheet 独立保留最后一次完整扫描；未修改时切换回来直接显示缓存，已修改时显示待更新。成功重新打开文件后清空上一会话。
11. 点击“导出清洗结果”，选择新文件位置，在确认窗口选择默认的“新增对照列（公式）”或“原列更新”，核对范围并确认。导出仍汇总所有 Sheet 的已应用修改，未应用预览或已撤销修改不会导出，源文件不覆盖。
12. 成功后可打开所在文件夹；公式模式需在 Excel 中计算结果。导出失败保留工作副本和历史，可再次导出；关闭前请导出希望保留的修改。

字符串预览加引号，隐藏字符用 `[NBSP]`、`[Tab]`、`[LF]`、`[CR]` 显示，方便识别差异。这些标记仅在显示层生成，不会替换实际数据。数字 0 显示为 `0`，文本 0 显示为 `"0"`，两者原有类型保留。

改动规则或策略后会清除旧预览并禁用应用，需重新生成。切换列、文件、Sheet 或重新检测后会重置清洗建议和预览。每次生成均基于当前工作副本的选中列，不在未应用的预览结果上叠加；预览中的“原始值”指本次操作前的工作数据。应用后相同规则再次生成预览时应为 0 行变化，应用按钮禁用，历史不增加。读取失败时保留先前成功读取的工作副本和历史。

### 整表扫描、质量分与缓存

`sheet_analyzer.analyze_sheet(df)` 按列位置遍历 `working_df`，调用 `detector.analyze_column(..., include_details=False)`，返回 `SheetAnalysis`。其中每个 `ColumnQuality` 保存列位置、字段名、总行数、受影响行数、九类计数、质量分、等级和最多三项的摘要。保留物理列位置，因此重名字段、非默认或重复的 DataFrame index 不会导致选错列。

单列与整表共用普通边缘空格、NBSP、Tab/LF/CR、空值和原始重复值规则。检测器一趟遍历收集文本问题、空值及重复分组，不对每种规则完整重扫一列。重复值排除 None / NaN / NA / 纯空字符串，重复数量包含首次出现，数字与文本不互转。

每个数据位置只有一个受影响标记；同一个单元格有空格、NBSP 和 Tab，也只计一个受影响行。质量分为：

```text
round(100 × (1 − affected_rows / total_rows))
```

结果限制在 0–100。分母为当前 DataFrame 的全部数据行，不包含表头，包含需要检测为空值的行。仅表头或零行列为 100 分；有 N 条空值的 N 行全空列为 0 分。例如 100 行中 2 行各有三种问题，受影响行数仍是 2，质量分为 98。95–100 为优秀、85–94 良好、70–84 建议清洗、0–69 问题较多。100 分只表示未发现当前九类问题。工作表级正常/问题字段数按各列是否存在受影响行统计，不将各列行数相加称为全表问题行数。

`SheetAnalysisWorker(QThread)` 在后台运行核心扫描，每完成一列通过 signal 发送进度，UI 只在主线程处理控件。扫描期间禁用打开、换 Sheet、选列、应用、撤销、恢复和导出，防止数据与结果错位。扫描快照只复制轻量 DataFrame 容器，不在主线程深拷贝整表；核心检测不赋值，而已有数据修改总是构建并替换工作副本。提交结果前再次检查文件会话、Sheet 和 revision，旧任务结果不覆盖当前状态。

取消使用协作中断：完成当前列后停止后续扫描，丢弃本轮不完整结果，保留上次完整缓存；取消与完成同时发生时也不发布已取消结果。关闭窗口会请求取消并等待线程退出，不强行终止 QThread。失败显示中文提示并恢复操作控件，已有完整缓存和工作数据保留。

每个 `SheetData.scan_cache` 保存结果和扫描时的 revision。应用、撤销、恢复、撤销恢复都增加对应 Sheet 的 revision，因此缓存自然失效；不会为显示总览自动扫描。过期页签标记“待更新”，上次统计明确标为过期，暂不可点击，重新扫描后恢复联动。单纯生成预览、无变化的应用、扫描或导出不会使缓存失效。重新打开文件创建新会话并清除旧缓存。

总览不保存全部问题明细或所有问题行号，避免 10 万行 × 50 列产生数百万条记录。点击字段时复用现有后台单列检测入口重新生成明细、推荐和清洗预览。本机验证 100,000 行 × 50 列（25 文本列、25 数字列，文本含空白、隐藏字符、空值与重复）扫描约 6.8 秒；后台扫描时 Qt 定时器仍持续响应。耗时取决于机器、文本长度与问题分布；文件读取时间另计。

### 原始快照、工作副本与历史

`WorkbookDataManager.sheet_data` 为每个已载入 Sheet 保存 `SheetData`。首次载入时复制出 `original_df`，再通过 `original_df.copy(deep=True)` 创建 `working_df`。数据表、检测与预览读取工作副本；应用清洗替换工作副本的目标原始字段，并刷新依赖它的辅助列标签；原始快照不参与赋值。

未访问的 Sheet 按需读取，首次载入后建立快照并缓存；再次访问直接使用缓存。成功打开另一文件或显式重开当前文件时清空所有旧 Sheet 状态、修改标记和历史；读取失败不重置原会话。

`PreparedPreview` 保存文件会话、Sheet、列位置、数据版本及前后值快照。规则改变会清空 UI 预览；数据应用、撤销、恢复或重新打开文件都会让相应版本失效。应用前及确认返回后均检查有效性，避免将旧预览应用到另一份数据。

`undo_stack` 按整本工作簿的操作顺序保存历史。`CleaningAction` 保存 Sheet、列名及位置、修改前后整列 Series、变化行位置、规则和时间；撤销恢复该源列并重新计算依赖辅助列。`AnnotationAction` 保存新增列的位置、名称和源字段；撤销完整删除该新增列。`RestoreAction` 保存恢复前的完整工作副本、辅助列元数据和修改状态，撤销恢复可回到恢复前。变化位置按数据顺序记录，支持重复的 DataFrame index，Excel 行号仍由预览记录显示。

撤销和恢复都不读取或写入源文件。历史保存在内存：清洗记录保存整列快照，恢复记录保存整表快照，数据量和历史长度会影响内存占用。

### 安全导出与保留范围

`get_export_snapshot()` 复制各个已载入 Sheet 的原始数据和当前工作数据，作为独立任务快照；`exporter.get_changes()` 比较当前值，返回 Sheet、Excel 行列位置、字段名、旧值和新值。缺失值之间不产生虚假变化，空字符串与缺失值区分。导出以当前差异为准，不依据过去的操作日志，因此撤销或恢复的修改不会重新出现。每列同时保存实际已应用的规则序列；撤销、恢复及撤销恢复会同步回滚规则，用于生成与当前工作副本一致的公式。未应用的勾选规则不会影响导出。

统一映射函数将数据行位置 0 映射为 Excel 第 2 行，将列位置 0 映射为第 1 列；不使用 DataFrame index 标签。复制后的文件按导入器相同约定重新读取，检查表头、列顺序和原始快照，再用 `openpyxl.load_workbook(data_only=False, rich_text=True)` 加载。“原列更新”只给原字段差异单元格的 `value` 赋值，原字段顺序不变；已应用辅助列另行追加到末尾。“新增对照列”在清洗列右侧插列，保留原始值、写入新表头和公式，并更新受影响的普通引用和结构。两种模式都不重建 Sheet、不插入或删除行，不使用 `pandas.to_excel()`，普通样式继续沿用原工作簿。

临时文件与目标文件位于同一目录。完成保存和校验后，Windows 使用不会覆盖已有文件的重命名发布；即使其他程序在保存期间创建了同名文件，导出也会取消。源文件仅用于读取和复制，从未调用 `save(source_path)`。导入前后、Sheet 首次载入、复制及导出前后检查 SHA-256；如果外部程序改动了源文件，需要重新打开后再操作。失败删除临时文件；若权限或文件占用阻止删除，会明确提示临时文件位置。

导出保留普通字体、背景、边框、对齐、数字格式、行高、列宽、合并区域、冻结窗格、筛选、Sheet 顺序与隐藏状态、打印设置和普通数据验证，相关行为使用真实工作簿测试。原列模式保留公式表达式；对照列模式调整受影响的普通 A1 引用，使公式继续引用原始单元格。若差异目标本身是公式，整个导出取消，不会用其缓存值覆盖公式。未修改的数值、空单元格和其他 Sheet 不逐格赋值；清洗成 `""` 的单元格在 Excel 中表现为空白。保留文本回车和纯空白字符串，避免 XML 写入器将未清洗的 CR 变成 LF，或让 Excel 丢弃原始的纯空格。

**保留范围受 openpyxl 能力限制，不能保证所有复杂 Excel 元数据原封不动。** 它会重新序列化 `.xlsx`，不会逐字节保留 ZIP 内容；公式缓存可能重置，需在 Excel 中重新计算，程序本身不计算公式。高级图形、部分扩展和复杂验证等需要单独测试；检测到 openpyxl 明确提示某扩展会丢失时取消导出。只支持 `.xlsx`，不支持 `.xls`、`.xlsm`、`.xlsb`，不承诺保留 VBA 宏。复杂重要工作簿建议先检查新导出的副本。

导出成功不会替换 `original_df`、清空工作副本或重置撤销历史。标题 `*` 和底部“已修改”仍表示与源文件存在差异；可以继续撤销、调整或再导出另一份新文件。

### 两种导出模式

| 模式 | 导出的副本 | 适合场景 |
|---|---|---|
| 原列更新 | 当前差异写入原列，保存清洗后的值；辅助列另行追加到末尾 | 保持现有数据结构，或处理复杂工作簿 |
| 新增对照列（公式，默认） | 原始脏数据保留，每个清洗列右侧生成一列公式结果 | 逐行对照、检查规则、保留原始值 |

例如原有“商品编码 / 商品名称”，清洗商品编码后，对照模式导出为“商品编码 / 商品编码_清洗后 / 商品名称”。同一列多次应用清洗，只生成一列最终结果；多个列和多个 Sheet 分别处理。字段重名时使用“字段名_清洗后_1”等唯一名称。

实际导出公式由 `export_formula_builder.py` 生成，按已应用规则的先后顺序处理。普通中间空格保留，数字 0、1002、12.5 不转为字符串，文本 `"0"` 保持文本，空白显示为空白。原列中的未修改公式在对照列中仅引用结果，不再执行文本清洗。NBSP 使用 `UNICHAR(160)` 精确匹配 Unicode U+00A0，避免 `CHAR(160)` 的本机编码差异；相关函数需要 Excel 2013 或更新版本。无需 LET、动态数组或 Ctrl+Shift+Enter。

软件不计算 Excel 公式。对照模式设置打开后自动重算；用支持这些函数的 Excel 打开并计算后显示结果。如果直接由不带计算引擎的程序读取新文件，公式缓存可能为空，需要先在 Excel 中打开并保存。公式单元格即使显示空白，也不是物理空单元格。

`column_inserter.py` 统一管理插列映射。支持普通 A1/绝对/跨 Sheet 引用和明确限定 Sheet 的定义名称，同时调整列宽、冻结窗格、可整体移动的合并区域、筛选、打印范围、普通数据验证及条件格式。验证和条件格式只跟随原有列，不自动施加到新结果列。原公式的范围若跨过插列位置，不会直接扩大范围，以免重复统计新结果列。

对照模式遇到无法安全调整的情况会取消导出并提示选择“原列更新”，包括动态地址、外部或结构化引用、跨 Sheet 区间、整行引用、跨插列的公式范围或合并区域、数组/数据表公式、相对全局定义名称、待修改 Sheet 的 Excel 表格对象，以及图形或透视表。公式长度、嵌套深度和最大列数超限也会明确拒绝。不会自动切换模式或偷偷改为固定值。

### 清洗顺序和统计

执行顺序集中定义在 `cleaner.py` 的 `ALL_RULE_ORDER` 中，单列与批量均依次执行勾选的规则；`RULE_ORDER` 保留基础字符规则顺序：

1. CHAR(160) / U+00A0 → 普通空格。
2. Tab / `\t` → 普通空格或直接删除。
3. 换行 / `\n` → 普通空格或直接删除。
4. 回车 / `\r` → 普通空格或直接删除。
5. 全角 ASCII 与全角空格转半角。
6. 去除字符串首尾的普通空格（U+0020）。
7. 安全文本数字转换。
8. 已明确确认字段含义的日期标准化。

例如 `"P001\u00a0"` 先变成 `"P001 "`，再变成 `"P001"`。`" ABC  123 "` 变成 `"ABC  123"`，中间两个空格保留。若同时将 CR 和 LF 替换为空格，CRLF 会产生两个普通空格，不自动压缩中间空格。

未启用高级日期规则时，数值 1002、0、12.5、None 和 NaN 等非字符串原样保留，不转换成文本。日期只在明确确认后标准化；空字符串不自动填充，重复行保留，不删除前导0，也不处理更广泛的 Unicode 或未知业务编码。

“发生变化”按数据行计数；操作明细只记录真正改变值的规则。“将被处理的问题”按实际执行操作涉及的单元格数统计，同一单元格可以涉及多个类别，数量总和不一定等于变化行数。首尾空格处理计数也包括前序字符替换后产生的首尾普通空格；Tab / 换行 / 回车合计按单元格去重。

### 公式参考

参考公式使用当前列首条数据的单元格引用，例如选中第二列时使用 `B2`，只组合本版本的 `SUBSTITUTE`、`UNICHAR`、`CHAR` 和 `TRIM`。例如勾选 CHAR(160) 和去首尾空格：

```excel
=TRIM(SUBSTITUTE(A2,UNICHAR(160)," "))
```

侧栏参考公式仅供文本处理学习和复制，不执行、不直接写入 Excel；Python 清洗逻辑与公式生成分别放在独立模块中。对照列导出使用独立的实际导出公式生成器。Excel 的 `TRIM` 还会压缩中间连续普通空格，而本程序只去首尾普通空格，因此参考公式和 Python 预览可能不同；实际结果以 Python 预览为准。参见 [Microsoft TRIM 函数说明](https://support.microsoft.com/zh-cn/excel/functions/trim-function)。

## V0.2 操作方法与统计口径

1. 点击“打开 Excel”，选择 `.xlsx` 文件，并切换到需要检查的工作表。
2. 在“工作数据”页点击表头选择某一列，顶部显示当前选择列。
3. 点击顶部“开始检测”，完成后自动进入“数据诊断”页，查看当前列、数据行数、九类统计及下方明细。明细列为：Excel行号、原始值、问题类型、问题说明。
4. 如需检查另一列，点击另一列表头后重新检测。未检测时数量显示“—”，完成且无问题时显示 0。

- **前后空格**仅检测字符串边缘的普通空格（U+0020），`ABC 123` 中间的普通空格不报错。
- **CHAR(160)**检测 U+00A0，按包含该字符的单元格数统计；说明包含位置及字符数量，明细包含对应 Excel 行号。
- **Tab / 换行**仅检测 `\t`、`\n`、`\r`；一个单元格有多种隐藏字符时，这一类只计 1 条，说明分别列出字符类型和数量。
- **空值**包括 None、pandas 缺失值及纯空字符串 `""`。数字 0 和文本 `"0"` 不算空值；仅含空格的字符串属于前后空格问题。
- **重复值**先排除空值，按原始值比较，不去空格、不替换字符、不将数字和文本互转。数值上相等的数字（如 1 和 1.0）视为同值；数字 1 与文本 `"1"` 不同。重复记录数包含每组首次出现，例如 A、A、A 计 3 条，不是 2 条。
- 问题明细保留原始值，一个单元格可以生成多条不同类型记录；重复组的每一行都会列出。较大重复组的说明只展示前 20 个行号，完整行号保存在结果的 `duplicate_groups` 中并逐行出现在明细表内。
- 第一行为表头时，首条数据对应 **Excel 第 2 行**。行号按数据位置计算，不使用 DataFrame index。
- 检测范围为当前已载入的工作表数据行；读取器不保留工作表末尾的全空行。公式沿用文件已有缓存值，不计算公式。

## 安装与启动

需要 **Python 3.11 或更高版本**。在项目目录打开 PowerShell：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

以上命令直接使用虚拟环境中的 Python，无需激活虚拟环境。已经安装依赖时，也可使用 `python main.py` 启动。

安装依赖后，可以双击项目目录中的 **`start.bat`** 启动。脚本优先使用项目的 `.venv`，没有虚拟环境时使用 PATH 中的 `python`，并自动切换到项目目录。异常退出时会显示错误信息并等待按键，避免错误窗口一闪而过。

### 启动后立即退出的排查方法

- 查看项目目录中的 `startup.log`，包含实际使用的 Python 路径、版本及错误详情。每次使用 `start.bat` 启动时会覆盖这份日志。
- 如果提示 `ModuleNotFoundError`，用启动时相同的 Python 安装 `requirements.txt`，例如 `.\.venv\Scripts\python.exe -m pip install -r requirements.txt`。

读取、检测、清洗、公式生成、状态管理及导出逻辑不依赖 Qt；界面通过表格模型展示数据。主窗口调度后台任务，业务规则和 Excel 写入不放在 UI 中。

`data_manager.py` 负责工作副本和撤销历史，不依赖 Qt，不包含文件保存方法。UI 只负责发起操作、显示确认和刷新；应用使用已经生成的预览快照，不重新执行另一套清洗规则。

界面主题在启动时由 `theme.py` 加载，优先使用系统中文字体。修改颜色、圆角、表格或按钮外观时，优先编辑 `app/ui/styles/light.qss`；图标放在 `app/ui/assets/`，布局由各 UI 组件管理。样式文件与图标按模块位置读取，从其他目录启动也可正常加载，无需增加运行依赖。

`detector.py` 中的 `detect_outer_spaces()`、`detect_nbsp()`、`detect_hidden_chars()`、`detect_empty_values()`、`detect_duplicates()` 是独立检测函数，接收 Series 和可选 Excel 起始行号，返回问题记录。`analyze_column()` 汇总为 `ColumnAnalysis`，包括列名、数据行数、各类计数、受影响唯一行数、全部明细和重复组；整表通过 `include_details=False` 省略明细，检测规则及计数保持相同。新增检测规则可沿用该模式，当前共实现约定的九类。

`cleaner.py` 提供独立的 `clean_outer_spaces()`、`clean_nbsp()`、`clean_tab()`、`clean_newline()`、`clean_carriage_return()`；`clean_hidden_whitespace()` 组合处理后三种隐藏字符。`CleaningRules` 记录勾选规则及处理策略，`apply_cleaning_rules()` 按集中定义的顺序处理单值，`generate_cleaning_preview()` 复制 Series 并返回 `CleaningPreview`，包含独立结果、逐行对比和统计。

`formula_builder.py` 只读取规则配置及执行顺序生成字符串，不调用清洗函数；`CleaningPreviewModel` 仅格式化显示，不把显示标记写回数据。

## 预览说明

- 总行数不包含字段名行；左侧行号是从 1 开始的数据行序号。
- 空工作表显示 0 行、0 列；只有字段名的工作表仍可显示表头并选择列。
- 预览使用 Excel 的单元格值，不复现 Excel 样式、合并单元格或数字显示格式。日期按读取后的值显示，公式使用文件已有的缓存结果，不计算公式。
- 重复字段名或空字段名采用 pandas 的默认命名规则，如 `字段.1` 和 `Unnamed: 0`。
- 当前会将所选工作表全部读入内存，未实现分页读取。文本中的前导零及 `NA` 等文本按原值读取，但不恢复仅由 Excel 数字格式产生的前导零。
